# v0.0.11-idx (Phase 11 index): Error handling evolution

Evolves API error handling in small incremental steps, preserving compatibility while moving from controller-local handling to a richer global contract.

## Prerequisites

Complete all prior guides through the **manual input validation phase**.

## Sub-phases for this phase

| Sub-Phase | Topic | Summary |
|-----------|-------|---------|
| 11a | **Global handling for known MVC errors** | Introduce `@RestControllerAdvice` for `MultiErrorException` and malformed JSON, remove controller-level duplication, and keep `{"errors":[...]}`. |
| 11b | **Catch-all for unexpected MVC errors** | Add `Exception.class` handler → `500` with generic reason phrase, log stack trace; framework request errors still fall through here until later sub-phases. |
| 11c-11f | **Reserved for later sub-phases** | Future sub-phases will be documented in their own guides when implemented. |

## How to proceed

1. Confirm prerequisites above.
2. Implement Sub-Phase **11a** (`v0.0.11a.md`) end to end.
3. Implement Sub-Phase **11b** (`v0.0.11b.md`) end to end.
4. Continue with the next guide in filename order.

For the full guide list, see [README.md](README.md).
