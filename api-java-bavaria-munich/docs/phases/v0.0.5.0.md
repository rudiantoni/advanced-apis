# v0.0.5 (Phase 5): API security layer

After [Phase 4](v0.0.4.md) (Postgres + JPA), the API has no authentication or authorization. Phase 5 adds a **security layer** so that non-public routes are rejected before they reach controllers.

Phase 5 is not a single implementation path. The documents **v0.0.5a**, **v0.0.5b**, and future **v0.0.5x** variants are **different approaches** to the same concern: protecting the API. Each subsection is self-contained — choose **one** approach and follow only that guide. They do not stack on top of each other.

## What every approach shares

Regardless of which subsection you pick, the security layer follows the same overall shape:

1. **Dependencies** — `spring-boot-starter-security` is added in Phase 5 (there is no security dependency before this). Subsection guides may add further libraries (for example JWT support in [v0.0.5b](v0.0.5b.md)).
2. **Configuration** — `app.security.*` in `application.yml` (or environment), read at startup. `spring.autoconfigure.exclude` drops the default in-memory user auto-configuration so the custom filter chain owns authentication.
3. **Public routes** — regex patterns in `app.security.public-routes` as a **JSON array** in YAML (for example `public-routes: "[\"^/open(/.*)?$\"]"`). Servlet paths matching any listed regex skip the security check; all other paths require valid credentials.
4. **Holders** — Phase 0 placeholders in `AppConsts` and `AppProperties` are replaced with real security fields. The Phase 0 `AppConfig` was only a demonstration hook and is **replaced** with constructor-based startup initialization.
5. **`AppConfig`** — injects `Environment` and the Spring `ObjectMapper`; private `init()` calls `initializeJsonUtil()` (wires `JsonUtil` to the shared `ObjectMapper`) and `initializeProperties()` (loads `app.security.*` into `AppProperties`).
6. **`JsonUtil`** — extended beyond `applyIfDefined` (Phase 3) with `setObjectMapper`, `fromJsonStr`, and `toJsonStr`; configuration parsing reuses the same Spring `ObjectMapper` (including `JsonNullable` support from `JacksonConfig`).
7. **`AppBeansConfig`** — separate `@Configuration` with `@DependsOn("appConfig")` that exposes compiled public-route regexes as a `List<Pattern>` bean (`publicUrlPatterns`) for the filter.
8. **Servlet filter** — a custom `OncePerRequestFilter` uses `publicUrlPatterns` to skip public paths, validates credentials on protected paths, and returns `401 Unauthorized` with body `{"message":"Unauthorized"}` when validation fails.
9. **Spring Security** — stateless session, CSRF disabled, `permitAll()` at the authorization layer; enforcement lives in the custom filter, registered before `UsernamePasswordAuthenticationFilter`.

Implementing two subsections in the same codebase (for example API key **and** JWT filters both active) is out of scope for these guides and requires a deliberate merge not documented here.

## Subsections (pick one)

| Doc | Approach | Summary |
|-----|----------|---------|
| [v0.0.5a](v0.0.5a.md) | **API key** | Shared secret in header `X-API-Key`; no login endpoint; clients send the same key on every protected request. |
| [v0.0.5b](v0.0.5b.md) | **JWT (basic, mock login)** | `POST /auth/login` with fixed mock credentials returns a Bearer token; `GET /users/me` reads claims from the token; protected routes require `Authorization: Bearer <token>`; no roles, no database user lookup. |

Future **v0.0.5x** documents may add other approaches (for example JWT with database-backed users or role-based access). Each new file should be treated as another alternative at the same phase level, not a mandatory next step after 5a or 5b.

## How to use this folder

1. Complete Phase 4 and confirm the API runs against Postgres.
2. Read this page and choose the approach that fits your learning or product goal.
3. Open the matching guide (**v0.0.5a**, **v0.0.5b**, or another subsection) and implement it end to end.
4. Ignore the other Phase 5 subsections unless you switch approach (typically on a branch or clean checkout).

For the incremental phase index, see [README.md](README.md).
