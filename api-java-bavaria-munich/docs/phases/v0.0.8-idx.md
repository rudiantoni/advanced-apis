# v0.0.8-idx (Phase 8 index): Authentication layer

Adds **credential validation** on protected routes. Each sub-phase below **replaces** `RouteProtectionFilter` with an auth-specific filter and extends configuration as needed.

## Prerequisites

Complete every **prior** guide in filename order through the **route-protection phase** (`public-routes`, `RouteProtectionFilter`, `AppBeansConfig.publicRouteRules`). The API must still run against **Postgres** when a sub-phase requires it. Read this index before implementing any authentication sub-phase below.

## Canonical path vs alternatives

On the **canonical guide path**, implement Sub-Phase **8a** (`v0.0.8a-official.md`) and **skip** Sub-Phases **8b**, **8c**, and **8d**. Later guides assume the official authentication sub-phase was implemented when they do not state otherwise.

Sub-Phases **8b**, **8c**, and **8d** remain in the repository as **reference alternatives** only. They are not part of the canonical sequence and are not prerequisites for Sub-Phase **8a**.

## Sub-phases for this phase

| Sub-Phase | Approach | Summary |
|-----------|----------|---------|
| 8a (**official**) | **JWT, database credentials** | Replaces `RouteProtectionFilter` with `JwtAuthFilter`; extends `public-routes`; JWT Bearer auth; `POST /auth/login` against Postgres `users`; public `POST /users`; BCrypt; `GET /users/me`. **Canonical path.** |
| 8b (alternative) | **API key** | Replaces `RouteProtectionFilter` with `ApiKeyAuthFilter`; shared secret in `X-API-Key` header. |
| 8c (alternative) | **Basic JWT, in-memory credentials** | Replaces `RouteProtectionFilter` with `JwtAuthFilter`; extends `public-routes` with `POST /auth/login`; `default-users` in configuration only. |
| 8d (alternative) | **Hybrid JWT, in-memory + database** | Same as **8c** plus database users, hybrid login, public `POST /users`. |

Future authentication sub-phase documents may add other approaches (for example roles). Each is another alternative under this phase, not a mandatory follow-up after the official sub-phase.

## What every approach shares

Regardless of which sub-phase you pick:

1. **Filter replacement** - remove `RouteProtectionFilter` from `SecurityConfig` and register `ApiKeyAuthFilter` or `JwtAuthFilter` in its place. The new filter reuses `publicRouteRules` and the same `isPublicRequest` logic, then validates credentials on protected requests.
2. **Configuration** - **extend** `app.security.*` and `AppProperties` / `AppConsts` from the route-protection phase; update `public-routes` when the approach requires additional public endpoints (for example `POST /auth/login`).
3. **OpenAPI** - extend `OpenApiConfig` with the matching security scheme (`apiKey` or `bearerAuth`) and align the customizer with that scheme name instead of `pendingAuth`.
4. **Unauthorized response** - protected requests with missing or invalid credentials still return `401` with body `{"message":"Unauthorized"}`.

JWT-specific libraries and login endpoints belong in Sub-Phase **8a**, **8c**, and **8d** guides only, not in **8b**.

Implementing two sub-phases in the same codebase (for example API key **and** JWT filters both active) is out of scope for these guides and requires a deliberate merge not documented here.

## How to proceed

**Canonical path:**

1. Confirm prerequisites above.
2. Implement Sub-Phase **8a** (`v0.0.8a-official.md`) end to end.
3. Ignore Sub-Phases **8b**, **8c**, and **8d** unless you deliberately switch approach (typically on a branch or clean checkout).

**Alternative path:**

1. Confirm prerequisites above.
2. Choose one row from the alternative sub-phase table (**8b**, **8c**, or **8d**).
3. Implement that sub-phase end to end.
4. Ignore the other authentication sub-phase guides unless you switch approach.
